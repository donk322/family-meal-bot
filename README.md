# Семейный бот для меню (без глютена)

Каждый вечер бот присылает каждому члену семьи кнопку голосования. Семья
голосует за блюда по категориям, а не заказывает лично себе: побеждает самый
популярный вариант в каждой категории. Так один повар готовит несколько блюд
на всех (шведский стол), а не 5–7 разных.

Меню **фиксированное**: 56 блюд с проверенными рецептами. ИИ меню больше не
придумывает. Бот считает голоса, пересчитывает рецепты победивших блюд на
нужное число порций, сверяет с запасами и присылает повару (он англоязычный)
подробный план готовки на английском. Сообщение повару собирает код, без
вызова ИИ.

## Из чего состоит

- `catalog/dishes_fixed.json` — каталог: 56 блюд. Его собирает
  `catalog/build_catalog.py` из текстов рецептов в `recipes_src/`. У каждого
  блюда: `id`, английское название для повара (`title`), русские название и
  описание для семьи (`title_ru`, `description_ru`), категория, базовое
  число порций (`base_portions`), ингредиенты (у каждого `stock_key`,
  единица, количество на базовые порции, флаг `staple`), шаги, признаки
  готовности, предупреждения, время старта и длительность.
- `recipes_src/*.txt` — исходные рецепты на английском, в том виде, в каком
  их получает повар. Это единственный источник правды для меню.
- `catalog/scale_recipe.py` — пересчёт рецепта на нужное число порций
  (`render_dish`), обратный отсчёт (`countdown_lines`). Если порций больше
  чем в полтора раза против базы, рецепт готовится несколькими партиями.
- `catalog/stock_check.py` — проверка запасов (`check_dish`), списание
  (`subtract_for_dish`) и пересчёт единиц между рецептом и складом (таблица
  `CONV`, например «1 bell pepper = 150 g»).
- `catalog/test_scale.py` — проверка пересчёта всех 56 блюд на 3–16 порций.
- `catalog/test_stock.py` — проверка запасов: допуск, пересчёт единиц,
  группы продуктов, списание.
- `test_menu_today.py` — список блюд для голосования (`/menu-today`) на
  тестовом стоке, `/people`, пустая категория, сообщение о нехватке для
  выбранного меню. Запуск из корня: `python test_menu_today.py`.
- `catalog/shopping_list.py` — список покупок для магазина (`/whatstobuy` и
  воскресный автосписок): что купить и сколько, по уровням срочности и
  отделам магазина.
- `catalog/report_now.py` — пример отчёта «что можно приготовить и что
  докупить» на тестовых запасах.
- `webapp/index.html` — экран голосования внутри Telegram, на русском
  (для семьи). Список блюд он берёт с сервера бота (`/menu-today`).
- `webapp/stock.html` — экран ввода запасов (команда `/updatestock`), на
  английском (для повара).
- `bot.py` — сам бот: напоминания, голоса, победители и порции, запасы,
  сообщение повару, недельный список покупок.
- `cook_photos/` — фото готовых блюд с подписями (`captions.json`). Бот их
  пока не использует.
- `webapp/images/` — фото блюд старого меню. Нынешний мини-апп их не
  показывает.
- `requirements.txt` — зависимости Python, `env.example` — шаблон настроек,
  `render.yaml` — настройки деплоя на Render.

## Голосование

| Приём пищи | Категории (по одному блюду в каждой) | Обязательно |
|---|---|---|
| Завтрак | Основное блюдо (10), Дополнение (лёгкое) (5), Десерт (3) | Основное блюдо |
| Ужин | Суп (8), Салат (7), Основное блюдо (15), Гарнир (6), Десерт (5) | Основное блюдо |

В скобках — сколько блюд в категории. На завтрак предлагаются только 3
десерта из 5, у которых в каталоге `breakfast_ok = true`. Один и тот же
десерт может победить и на завтрак, и на ужин: голоса считаются отдельно.

В мини-аппе показываются только блюда, на которые хватает продуктов на
запланированное число порций приёма пищи: едоков (`BREAKFAST_PEOPLE` = 5,
`DINNER_PEOPLE` = 7 или число из `/people`) плюс `PORTION_BUFFER_EXTRA`.
Десерт завтрака проверяется на порции завтрака, десерт ужина — на порции
ужина. Список считается заново при каждом открытии мини-аппа по текущим
запасам, поэтому после `/people 9 11` он короче. Голос за блюдо, которое
пропало из списка уже после голосования, всё равно засчитывается. Если в
обязательной категории (основное блюдо завтрака или ужина) нет ни одного
блюда, голосование не блокируется: на сегодня категория необязательная, в
мини-аппе в ней строка «Нет доступных блюд: докупите продукты». Если основного блюда в итоге нет, повар получает в этой секции
«No main dish selected», а создатель — предупреждение. Продукта считается достаточно, если есть не меньше 90% нужного или,
когда нужно до 100 г/мл, не хватает не больше 5 г/мл. Если продукта нет в
запасах вообще или осталось 0, блюда нет в списке. Соль, перец, масло, сухие
специи, уксус, горчица и вода (`staple`) не проверяются и не списываются.

Голос главы семьи (`FAMILY_HEAD_USERNAME`) весит `FAMILY_HEAD_VOTE_WEIGHT`
(по умолчанию 2). Вес влияет на победителя, но не на число порций.

## Как это работает день за днём

1. В 16:30 (`EMPTY_MAIN_ALERT_HOUR:EMPTY_MAIN_ALERT_MINUTE`) бот проверяет,
   есть ли хоть одно доступное основное блюдо на завтрак и на ужин (так же,
   как список в мини-аппе: на запланированные порции). Если нет,
   создатель и глава семьи получают строку «Нет доступных основных блюд на
   ужин. Список покупок: /whatstobuy».
   В `REMINDER_HOUR:REMINDER_MINUTE` бот шлёт кнопку голосования каждому из
   семьи. В `NUDGE_HOUR:NUDGE_MINUTE` ещё раз напоминает тем, кто не
   проголосовал, и присылает карточки оценки сегодняшних блюд. Создателю и
   главе семьи в это же время приходит строка «Завтра: завтрак 5 чел.,
   ужин 7 чел. Изменить: /people».
2. В `COMPILE_HOUR:COMPILE_MINUTE` бот:
   - определяет победителя в каждой категории;
   - считает порции: едоков берётся больше из двух чисел — сколько обычно
     едят (`BREAKFAST_PEOPLE` = 5 на завтрак без школьников,
     `DINNER_PEOPLE` = 7 на ужин, либо число из `/people`) и сколько
     человек проголосовало в этом приёме пищи. К этому прибавляется
     `PORTION_BUFFER_EXTRA` (по умолчанию +2 на добавку). В сообщении
     повару это видно в заголовке: «BREAKFAST (5 people + 2 extra = 7
     portions)», с пометкой «(guests)», если число задано через `/people`;
   - отдельно готовит ранний завтрак школьников: основное блюдо завтрака на
     `KIDS_BREAKFAST_COUNT + KIDS_BREAKFAST_BUFFER` порций (по умолчанию 3);
   - списывает со склада продукты на всё, что будет приготовлено, включая
     завтрак школьников. Нехватка копится в недельный список покупок. Если
     для выбранного меню в сумме не хватает продуктов (например, два блюда
     на один сыр), создатель и глава семьи получают «Для выбранного меню не
     хватает: сметана — 150 мл. Купите до готовки. /whatstobuy».
     Сообщение повару от этого не меняется;
   - если продукта осталось меньше чем на `LOW_STOCK_SERVINGS` порций,
     сразу предупреждает повара;
   - собирает сообщение повару: вступление, завтрак школьников, завтрак и
     ужин (у каждого обратный отсчёт, рецепты на нужное число порций и
     финальная проверка). Сообщение делится на части по границам блюд.
     Блюдо длиннее лимита Telegram (сейчас это только сэндвич со стейком)
     уходит двумя сообщениями с пометками «(part 1 of 2)» и «(part 2 of 2)».
3. Раз в неделю, по умолчанию в воскресенье в 21:35 (`WEEKLY_SHOPPING_DAY`
   = 6, где 0 = понедельник … 6 = воскресенье, и
   `WEEKLY_SHOPPING_HOUR:WEEKLY_SHOPPING_MINUTE`), бот присылает повару
   список покупок, копией — создателю и главе семьи. Это тот же список, что
   по `/whatstobuy` (`catalog/shopping_list.py`), по текущим запасам, без
   ИИ. Бот больше нигде не вызывает Claude.
4. После похода в магазин повар отправляет боту строки `/addstock` из конца
   списка покупок (лишнее удалить, количества поправить).

Повторная сборка в тот же день (`/forcecompile`) не списывает запасы второй
раз: бот откатывает их к состоянию до первой сборки.

## Запасы

Запасы лежат в `data/inventory.json`. Старые продукты хранятся под русскими
названиями (`говяжий фарш`, `г`), новые — под английскими, как их ввели в
`/addstock`. Бот переводит русские названия в английские ключи каталога
(таблица `INGREDIENT_EN` в `bot.py`), килограммы и литры считает в граммах и
миллилитрах и складывает одинаковые продукты.

Если в рецепте и на складе разные единицы (в рецепте «2 red onions», на
складе граммы), пересчёт задаётся в `CONV` в `catalog/stock_check.py`.
Несколько видов одного продукта (например, разные грибы) складываются по
`STOCK_GROUPS` там же.

## Как поменять или расширить меню

1. Поправьте или добавьте рецепт в нужный файл `recipes_src/` в том же
   формате, что и остальные (заголовок между линиями ━ с «— serves N»,
   блоки YOU NEED, шаги, ✅ и ⚠️ строки).
2. Для нового блюда добавьте в `catalog/build_catalog.py` строку в
   `CATEGORY_RULES` (категория по части английского названия) и в
   `NAMES_RU` (русские название и описание). Десерт, который можно на
   завтрак, добавьте ещё и в `BREAKFAST_DESSERTS`. Новый продукт с
   английским названием, которое не совпадает с ключом склада, добавьте в
   `NAME_MAP`.
3. Пересоберите каталог и проверьте пересчёт:

   ```
   cd catalog
   python build_catalog.py
   python test_scale.py
   python test_stock.py
   ```

   Должно быть «Проблемы разбора: нет» и дважды «Ошибок: 0». На Windows, если
   консоль ругается на кодировку, запускайте `python -X utf8 ...`.
4. Закоммитьте `recipes_src/` вместе с обновлённым
   `catalog/dishes_fixed.json`. Мини-апп менять не нужно: он берёт блюда с
   сервера.

## Полезные команды в боте

- `/help` — справка на английском для повара
- `/updatestock` — экран, где можно быстро вписать, сколько чего есть
- `/shoppinglist` — что накопилось в недельном списке покупок на данный момент
- `/rate` — оценить сегодняшние блюда (вкус и размер порции)
- `/whoami` — узнать chat_id текущего чата

Запасы — только для повара (`COOK_CHAT_ID`), создателя и главы семьи,
остальным бот вежливо отказывает:

- `/stock` — текущие запасы
- `/addstock название количество единица` — добавить купленное (единицы g,
  kg, ml, l, pcs), можно вставить сразу много строк. Если строк больше 5,
  бот отвечает одним компактным отчётом «Добавлено N позиций:» со строками
  «название: +количество → итого», а строки с ошибками (непонятная
  единица, не число) перечисляет в конце. Если продукт уже есть в запасах
  в килограммах, добавленные граммы пересчитываются в килограммы; граммы к
  штукам не прибавляются — такая строка уходит в ошибки
- `/removestock название` — убрать продукт из запасов
- `/whatstobuy` — список покупок на английском: только что купить и
  сколько. Три уровня: 🔴 URGENT — BUY TODAY (сыр, чеснок, сметана,
  сливки, бекон, грибные кубики — только те, что кончаются), 🟠 ALSO
  NEEDED (остальная основа), ⚪ OPTIONAL (продукты для отдельных блюд);
  внутри — разделы магазина. В конце — готовые строки `/addstock` с
  рекомендованными количествами (лишнее удалить, отправить боту после
  покупок)

Только для создателя и главы семьи (`CREATOR_CHAT_ID`, `FAMILY_HEAD_CHAT_ID`,
`FAMILY_HEAD_USERNAME`):

- `/previewcook` — прислать себе сообщения повара по текущим голосам. Повару
  ничего не уходит, запасы и история не меняются
- `/forcecompile` — собрать и отправить план повару прямо сейчас
- `/people` — сколько человек будет завтра (гости). Без аргументов —
  кнопки «Завтрак −/+», «Ужин −/+», «Сбросить», «Готово» (1..30 человек;
  «Готово» ставит 1 день). `/people 6 9` — завтрак 6, ужин 9 на один день,
  `/people 6 9 3` — на 3 дня, `/people reset` — как обычно. Каждая
  успешная сборка для повара расходует один день; когда дни кончаются,
  снова считается как обычно. Состояние лежит в `data/headcount.json`.
  Повторная сборка в тот же день (`/forcecompile`) лишний день не тратит.

`/regenmenu` остался для совместимости и отвечает, что меню фиксированное.

## Установка

1. **Бот.** `@BotFather` в Telegram → `/newbot`. В конце будет `BOT_TOKEN`.
2. **Мини-приложения.** Нужен хостинг статики с HTTPS (сейчас GitHub Pages).
   `.../webapp/index.html` — это `MINI_APP_URL`, `.../webapp/stock.html` —
   `STOCK_APP_URL`. Адрес сервера бота прописан в `API_BASE_URL` в обоих
   файлах.
3. **Настройки.** Скопируйте `env.example` в `.env` и заполните
   `BOT_TOKEN`, `MINI_APP_URL`, `STOCK_APP_URL`. Ключ Claude API боту больше
   не нужен.
4. **Запуск.**

   ```
   pip install -r requirements.txt
   python bot.py
   ```

   Не запускайте бота локально с тем же `BOT_TOKEN`, пока работает версия
   на Render: Telegram разрешает только один экземпляр, второй получит
   ошибку 409 Conflict.
5. **Деплой на Render.** `render.yaml` описывает бесплатный Web Service. Бот
   поднимает маленький HTTP-сервер на `$PORT`: через него работают
   `/menu-today` и `/current-stock` для мини-аппов, а
   внешний пингер (например, UptimeRobot) не даёт сервису уснуть.
6. **Повар.** Пусть повар напишет боту `/whoami` (не `/start`, чтобы не
   попасть в список голосующих). Число из ответа впишите в `COOK_CHAT_ID`.
7. **Семья.** Каждый один раз пишет боту `/start`.

## Что можно донастроить

Всё через переменные окружения (полный список в `env.example`): время
напоминаний, сборки и недельного списка, часовой пояс `TIMEZONE` (по
умолчанию `Africa/Johannesburg`, сервер работает по UTC), обычное число
едоков `BREAKFAST_PEOPLE` и `DINNER_PEOPLE` (по умолчанию 5 и 7, задавать
необязательно), запас порций `PORTION_BUFFER_EXTRA`, порог `LOW_STOCK_SERVINGS`, число школьников
`KIDS_BREAKFAST_COUNT` и запас `KIDS_BREAKFAST_BUFFER`, вес голоса главы
семьи `FAMILY_HEAD_VOTE_WEIGHT`.

## Ограничения этой версии

- На бесплатном Render диск временный: `data/` (семья, запасы, голоса,
  история) стирается при каждом деплое и перезапуске сервиса.
- Постные блюда, блюда «на одного», прожарка и способ приготовления яиц
  из пожеланий в этой версии не обрабатываются. Поле комментариев в
  мини-аппе сохраняется вместе с голосом, но в сообщение повару не попадает.
- Если до времени сборки никто не проголосовал, повару в этот день ничего
  не придёт.
