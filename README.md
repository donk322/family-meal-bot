# Семейный бот для меню (без глютена)

Каждый вечер бот присылает каждому члену семьи кнопку голосования — семья
голосует за блюда по категориям, а не заказывает лично себе. Побеждает
самый популярный вариант в каждой категории, что позволяет одному повару
готовить максимум несколько блюд в день (шведский стол), а не 5-7 разных.
Бот считает нужное количество продуктов на победившие блюда, сверяет с
запасами, и присылает повару (он англоязычный) подробный план готовки —
на английском, с полными пошаговыми рецептами.

## Из чего состоит

- `dishes.json` — каталог блюд: 26 блюд (10 завтраков, 10 основных ужинов,
  2 стартера, 2 гарнира, 2 десерта — десерты общие для завтрака и ужина), у
  каждого — название, описание, ингредиенты с количеством на порцию,
  подробный пошаговый рецепт, время готовки и как подавать. Это единственный
  источник правды для меню и для расчёта продуктов
- `webapp/index.html` — экран голосования, который открывается внутри
  Telegram по кнопке. Голосование по категориям: Завтрак (Основное +
  Десерт), Ужин (Стартер, Основное, Гарнир, Десерт) — в каждой категории
  выбор одного варианта. Каждая карточка блюда ждёт фото по пути
  `webapp/images/<id>.jpg` — пока фото нет, вместо него показывается
  эмодзи-заглушка. Список блюд в нём продублирован (только название и
  описание, без рецептов) — если меняете `dishes.json`, не забудьте обновить
  и этот файл. Мини-апп на русском — им пользуется семья
- `webapp/stock.html` — экран для быстрого ввода текущих запасов на кухне
  (открывается командой `/updatestock`). На английском — им пользуется повар
- `webapp/images/NEEDED_PHOTOS.txt` — список из 26 точных имён файлов,
  которые нужны (по одному на блюдо)
- `bot.py` — сам бот: рассылает напоминания, собирает голоса, считает
  победителей и порции, сверяет с запасами, вызывает Claude для финального
  оформления плана на английском, отправляет план и список покупок повару
- `requirements.txt` — зависимости Python
- `.env.example` — шаблон настроек

## Шаг 1. Создать бота

Напишите `@BotFather` в Telegram → `/newbot` → следуйте инструкциям.
В конце вы получите `BOT_TOKEN`.

## Шаг 2. Разместить мини-приложение

Нужен любой бесплатный хостинг статики с HTTPS — например GitHub Pages,
Netlify или Vercel. Загрузите туда всю папку `webapp` (там и `index.html`,
и `stock.html`) и получите ссылку вида `https://ваш-сайт.netlify.app` —
`https://ваш-сайт.netlify.app/index.html` это `MINI_APP_URL`, а
`https://ваш-сайт.netlify.app/stock.html` — это `STOCK_APP_URL`. Оба файла
разворачиваются одним и тем же способом, отдельно ничего настраивать не
нужно.

## Шаг 3. Получить ключ Claude API

Зарегистрируйтесь на `console.anthropic.com`, создайте API-ключ —
это `ANTHROPIC_API_KEY`.

## Шаг 4. Настроить .env

Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`,
`ANTHROPIC_API_KEY` и `MINI_APP_URL`. `COOK_CHAT_ID` пока оставьте пустым —
заполните на шаге 6.

## Шаг 5. Запустить бота

```
pip install -r requirements.txt
python bot.py
```

Чтобы бот работал постоянно, а не только пока запущен у вас на компьютере,
разместите его на бесплатном тарифе Render или Railway (тип сервиса —
Background Worker), указав те же переменные из `.env` в настройках сервиса.
Файл `dishes.json` должен лежать рядом с `bot.py` в той же папке — при
деплое убедитесь, что он тоже загружен на сервер.

## Шаг 6. Узнать chat_id повара

Пусть повар напишет боту `/start`, а затем `/whoami` — бот пришлёт число вида
`chat_id этого чата: 123456789`. Впишите это число в `COOK_CHAT_ID` в `.env`
и перезапустите бота.

## Шаг 7. Остальные — тоже /start

Каждый член семьи один раз пишет боту `/start` — так бот запомнит, кому
отправлять вечерние напоминания. Дальше всё работает само.

## Шаг 8. Добавить фото блюд (через Claude Code)

Мини-апп уже готов показывать фото — просто пока их нет. У Claude в чате
(там, где собирался этот проект) нет доступа скачивать файлы с произвольных
сайтов, а вот у **Claude Code на вашем компьютере есть полноценный интернет**,
поэтому эту часть лучше сделать именно там.

Попросите Claude Code примерно так:

```
Открой webapp/images/NEEDED_PHOTOS.txt — там список из 20 файлов.
Найди подходящее фото для каждого блюда (по его названию) и сохрани
в webapp/images/ строго под тем именем файла, что указано в списке.
```

Как только файлы появятся в `webapp/images/` с правильными именами,
карточки в меню сами подхватят фото — ничего больше менять не нужно.

## Шаг 9. Занести начальные запасы (необязательно, но полезно)

Запасы стартуют пустыми — то есть в первый день всё, что понадобится, попадёт
в список покупок целиком. Если у вас уже что-то есть дома, можно занести это
заранее командами вида:

```
/addstock яйца 12 шт
/addstock молоко 1000 мл
/addstock картофель 2000 г
```

Названия ингредиентов должны точно совпадать с теми, что в `dishes.json`
(иначе бот будет считать это разными продуктами) — свериться можно, открыв
файл и посмотрев поле `name` у нужного ингредиента.

## Как это работает день за днём

Семья не заказывает себе еду лично — она **голосует**, а побеждает самый
популярный вариант в каждой категории. Это сделано специально: один повар
физически не может готовить 5-7 разных блюд одновременно, а голосование
превращает это в шведский стол максимум из нескольких блюд.

1. Вечером в `REMINDER_HOUR` бот шлёт кнопку голосования каждому из семьи
2. Каждый голосует по категориям — ровно один вариант в каждой:
   - Завтрак: Основное (обязательно) + Десерт (по желанию)
   - Ужин: Стартер, Основное (обязательно), Гарнир, Десерт — все, кроме
     Основного, по желанию
   Для блюд с яйцом или мясом можно указать желаемую прожарку. Есть общее
   поле для комментариев (аллергии, нелюбимые продукты и т.д.)
3. Блюда, для которых прямо сейчас не хватает ингредиентов (даже одного),
   показываются потускневшими и недоступны для выбора — это сверяется в
   реальном времени через эндпоинт `/availability` на сервере бота
4. В `COMPILE_HOUR:COMPILE_MINUTE` бот:
   - считает голоса и определяет одного победителя в каждой категории
   - считает порции — все, кто голосовал в этом приёме пищи, плюс
     `PORTION_BUFFER_EXTRA` (запас на добавку, по умолчанию +1)
   - складывает нужное количество ингредиентов на победившие блюда,
     вычитает из запасов (`data/inventory.json`)
   - оставшийся излишек остаётся в запасах на будущее, нехватка копится в
     недельный список покупок (не отправляется каждый день)
   - если какого-то продукта осталось совсем мало — сразу шлёт отдельное
     предупреждение (см. ниже)
   - просит Claude аккуратно оформить план **на английском языке** (повар
     англоязычный), сохраняя все подробные шаги рецептов дословно, с
     пометками по прожарке и аллергиям, в формате шведского стола (одна
     общая посуда на блюдо, а не персональные тарелки)
   - отправляет повару план готовки на завтра — без списка покупок
5. Раз в неделю, в `WEEKLY_SHOPPING_DAY` (0=понедельник … 6=воскресенье) в
   `WEEKLY_SHOPPING_HOUR:WEEKLY_SHOPPING_MINUTE`, бот присылает один общий
   список покупок на всю неделю (на английском)
6. После похода в магазин кто угодно пишет боту `/restock` — и всё, что было
   в последнем присланном (недельном) списке, добавляется обратно в запасы

## Повар — англоязычный

Все сообщения, которые видит повар (ежедневное меню, список покупок,
предупреждение о нехватке, ответы `/stock` и `/whatstobuy`), — на английском.
Мини-апп с меню (которым пользуется семья для голосования) — на русском,
его не трогали. Экран пополнения запасов `webapp/stock.html` тоже на
английском, потому что запасами занимается повар — внутри данные всё равно
хранятся под русскими названиями, чтобы совпадать с `dishes.json`.

Чтобы подключить повара отдельно от семьи (не добавляя его в список
голосующих): пусть повар напишет боту именно `/whoami` (не `/start`),
пришлёт вам число, а вы впишете его в `COOK_CHAT_ID` на Render.

## Полезные команды в боте

- `/help` — краткая справка на английском для повара: что делает бот и
  какие команды доступны
- `/stock` — посмотреть текущие запасы (повару — на английском)
- `/whatstobuy` — что докупить, чтобы открыть больше блюд из меню, с точным
  количеством нехватки (повару — на английском)
- `/updatestock` — открыть экран, где можно быстро вписать, сколько чего
  есть на кухне (например, после большой закупки на неделю вперёд) —
  быстрее, чем вбивать `/addstock` по одному товару
- `/addstock название количество единица` — добавить продукт вручную
  (например, `/addstock мука 500 г`)
- `/restock` — пополнить запасы по последнему присланному списку покупок
  (после того как сходили в магазин)
- `/whoami` — узнать chat_id текущего чата

## Если что-то заканчивается раньше недели

Помимо недельного списка, бот каждый день после расчёта запасов сам
проверяет: если какого-то продукта осталось меньше чем на
`LOW_STOCK_SERVINGS` порций (по умолчанию 8 — примерно одна типичная партия
на всю семью), он сразу пишет повару предупреждение на английском — не
дожидаясь конца недели. Это подстраховка на случай, если что-то
расходуется быстрее, чем ожидалось.

## Как поменять или расширить меню

Откройте `dishes.json`, добавьте новый блок в том же формате (уникальный id,
`meal_type`: `breakfast` или `dinner`, ингредиенты на одну порцию, шаги
рецepta, способ подачи). Затем добавьте то же блюдо (только `id`, `name`,
`description`) в массив `BREAKFAST_DISHES` или `DINNER_DISHES` внутри
`webapp/index.html`, иначе оно не появится в меню у семьи.

## Что можно донастроить

- Время напоминания и время сборки плана для повара — переменные
  `REMINDER_HOUR`, `COMPILE_HOUR`, `COMPILE_MINUTE` в `.env`
- День и время недельного списка покупок — переменные `WEEKLY_SHOPPING_DAY`
  (0=понедельник … 6=воскресенье, по умолчанию воскресенье), `WEEKLY_SHOPPING_HOUR`,
  `WEEKLY_SHOPPING_MINUTE` в `.env`
- Часовой пояс — переменная `TIMEZONE` в `.env` (по умолчанию
  `Africa/Johannesburg`). Это важно: сервер, на котором будет жить бот,
  почти наверняка работает по UTC, а не по вашему местному времени, поэтому
  часовой пояс задан явно и не зависит от того, где физически стоит сервер
- Модель Claude — сейчас используется `claude-sonnet-5`; можно заменить на
  более дешёвую `claude-haiku-4-5-20251001` в `bot.py`, если не нужна
  максимальная подробность форматирования каждый раз

## Ограничения этой версии

- Данные хранятся в простых JSON-файлах в папке `data/` — этого достаточно
  для одной семьи, но при желании файлы легко заменить на настоящую базу
  данных
- Инвентарь считает по названию продукта как по строке — `лук` и
  `лук репчатый` для бота два разных продукта, поэтому названия в
  `dishes.json` стоит держать едиными
- Если ответ никто не пришлёт до времени сборки, повару просто ничего не
  придёт в этот день
- Каждый выбирает ровно одно блюдо на завтрак и одно на ужин — блюдо для
  нескольких человек сразу не предусмотрено (общий стол не считается)
